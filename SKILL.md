# Init Work

## Overview

Create one initialized `tasks/<english-slug>/` workspace in the user's current Git repository from the bundled template. Collect only information that cannot be derived reliably; generate all remaining values without asking the user.

## Conversation contract

Reuse answers already supplied in the user's request or this task's conversation. Ask only for missing values, one question per turn, in this order:

1. `TASK_NAME`: “작업 이름은 무엇인가요?”
2. `START_NAME`: “착수자 이름은 무엇인가요? 없으면 ‘없음’이라고 답해주세요.”
3. `REFERENCE_PATHS_OR_NONE`: “조사하거나 참조할 경로가 있나요? 없으면 ‘없음’이라고 답해주세요.”
4. `ADDITIONAL_EDIT_SCOPE_OR_NONE`: “작업 폴더 밖에서 추가로 편집을 허용할 경로가 있나요? 없으면 ‘없음’이라고 답해주세요.”

Once all four values are known, ask one additional summary question only when the supplied context does not reveal both the intended work and expected outcome: “이 작업의 목적과 기대 결과를 한 문장으로 설명해주세요.” If all values and the purpose are already clear, proceed directly to generation. Do not ask the user for the slug, dates, or a summary that can be derived confidently. Treat explicit “없음” as an answer; do not infer additional edit permission from reference paths or from silence.

## Derived values

| Value | Rule |
|---|---|
| `TASK_SLUG` | Name the core topic with 1–2 English keywords, such as `log-level`; use a third keyword only when needed to distinguish the topic. Omit generic action words (`organize`, `improve`, `implement`) and incidental details rather than translating the full task name. Use lowercase ASCII kebab-case matching `^[a-z0-9]+(?:-[a-z0-9]+)*$`; keep the full meaning in `TASK_NAME` and `TASK_SUMMARY`. |
| `TASK_SUMMARY` | Write one or two Korean sentences describing the work and expected outcome, using the clarification answer only when one was requested. |
| `START_DATE` | Generated by the script from Korean local time as `YYYY-MM-DD`. |
| `BASELINE_DATETIME` | Generated by the script from Korean local time as `YYYY-MM-DD HH:mm`, without an offset suffix. |
| `INITIAL_NEXT_ACTION` | Read reference instructions and entry documents when reference paths exist; otherwise define work units and completion criteria from the task scope. |

Normalize an empty or whitespace-only answer, `none`, or `없음` to `없음` for `START_NAME`, `REFERENCE_PATHS_OR_NONE`, and `ADDITIONAL_EDIT_SCOPE_OR_NONE`. Format supplied repository paths with backticks and separate multiple paths with commas. Preserve any short explanation that identifies a path's role.

## Generate the task

Resolve `<skill-dir>` as the absolute directory containing this loaded `SKILL.md`, whether installed locally or globally. Resolve `<repo-root>` separately as the Git root of the user's target project, not the skill's installation or source repository. Check that Git, `uv`, and the bundled script and template are available. If the target is not in a Git working tree or a prerequisite is missing, report what is needed before generating files. Confirm `tasks/<TASK_SLUG>/` does not exist in that target repository, then run:

```text
uv run "<skill-dir>/scripts/create_task.py" --repo-root "<repo-root>" --task-name <TASK_NAME> --task-slug <TASK_SLUG> --task-summary <TASK_SUMMARY> --start-name <START_NAME> --reference-paths <REFERENCE_PATHS_OR_NONE> --additional-edit-scope <ADDITIONAL_EDIT_SCOPE_OR_NONE>
```

Pass each placeholder as one shell argument using quoting appropriate to the current shell. Git and `uv` must be available; `uv` manages Python 3.11+ and the dependencies declared in the script. The script resolves `assets/task-template` relative to its own installation, so no template path override is needed. It requires a Git working tree, copies seven documents, derives the initial next action, replaces every token, and refuses invalid slugs or existing destinations. It preserves existing Git local exclusions and appends exact task-relative paths for `AGENTS.md` and `CLAUDE.md` to the Git-resolved `info/exclude` (including linked worktrees). It does not change `.gitignore`.

`README.md` owns the shared overview, document map, team rules, and scope. `AGENTS.md` contains local agent operating instructions and points to README; `CLAUDE.md` contains only `@AGENTS.md`. Keep both local and uncommitted; the other five documents are shared deliverables. `ROADMAP.md` is the briefing projection; `PROGRESS.md` is the detailed status source of truth. Keep the ROADMAP sequence table, adding a Mermaid `flowchart` with matching work IDs when branching, parallel execution, gates, or rollback paths make the flow complex. Do not add optional-module questions or generation branches.

## Growth after initialization

The generated README defines how later work-content and subtrack additions are incorporated: classify existing-work refinement versus an independent track, record confirmed scope changes and impacts in `decisions.md`, preserve existing IDs and completed history, then synchronize README scope, PROGRESS completion criteria/dependencies/next actions, and ROADMAP sequence. Create detailed documents only when needed and link them in the document map. An authorized content expansion does not expand editable paths. These are rules for working in the generated workspace, not a second generator mode or permission to modify the reference tasks.

After the command succeeds, inspect the created directory and report its path, slug, start date, and baseline time. If the slug is rejected, generate a valid English slug and retry once. If the destination already exists, do not overwrite or silently choose another name; report the conflict and ask the user how to proceed.

## Example

`로그 레벨 조정` becomes `log-level`; `문서 구조 정리` becomes `documentation`; `사용자 인증 토큰 갱신 기능 개선` becomes `token-refresh`. References such as `docs/` and `src/` become `` `docs/`, `src/` ``. If the short slug already exists, follow the conflict rule above; do not append arbitrary words, dates, or numbers automatically.

## Common mistakes

- Do not repeat answered questions or batch the remaining questions into one message.
- Do not resolve the generator path relative to the target repository; use the loaded skill's directory.
- Do not use Korean, romanized Korean, underscores, or spaces in `TASK_SLUG`.
- Do not turn the full task title into a long slug or shorten it with cryptic abbreviations or character truncation. Select the core topic words.
- During task creation, copy the asset template; do not customize the source assets for that task.
- Do not pre-generate optional modules; later work may add documents under the README growth rules.
- Do not include a UTC offset in the generated baseline time.
