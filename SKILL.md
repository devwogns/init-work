# Init Work

## Overview

Create one initialized seven-document task workspace from the bundled template. The user chooses the output location automatically or by entering a path, and the location decides the template: **global** (official project instructions at a Git repository root) or **sub** (a task folder inside a repository with local-only instructions). Collect only information that cannot be derived reliably; generate all remaining values without asking the user.

## Conversation contract

Reuse answers already supplied in the user's request or this task's conversation. Ask only for missing values, one question per turn, in this order:

0. Path mode: “저장 경로를 자동으로 정할까요, 직접 입력할까요?” When the user chooses manual input, ask next: “작업 문서를 만들 경로를 입력해주세요. 예: `C:/Path/project`”
1. `TASK_NAME`: “작업 이름은 무엇인가요?”
2. `START_NAME`: “착수자 이름은 무엇인가요? 없으면 ‘없음’이라고 답해주세요.”
3. `REFERENCE_PATHS_OR_NONE`: “조사하거나 참조할 경로가 있나요? 없으면 ‘없음’이라고 답해주세요.”
4. `ADDITIONAL_EDIT_SCOPE_OR_NONE`: “작업 폴더 밖에서 추가로 편집을 허용할 경로가 있나요? 없으면 ‘없음’이라고 답해주세요.” Ask this only when the plan's `template` is `sub`. For `global`, the work folder is the whole repository: do not ask, and pass `없음`.

Run the placement plan (below) as soon as `TASK_SLUG` can be derived, so the template is known before question 4. Once the values are known, ask one additional summary question only when the supplied context does not reveal both the intended work and expected outcome: “이 작업의 목적과 기대 결과를 한 문장으로 설명해주세요.” If all values and the purpose are already clear, proceed to the final confirmation. Never skip the final confirmation, even when the request supplied every value. Do not ask the user for the slug, dates, or a summary that can be derived confidently. Treat explicit “없음” as an answer; do not infer additional edit permission from reference paths or from silence.

## Derived values

| Value | Rule |
|---|---|
| `TASK_SLUG` | Name the core topic with 1–2 English keywords, such as `log-level`; use a third keyword only when needed to distinguish the topic. Omit generic action words (`organize`, `improve`, `implement`) and incidental details rather than translating the full task name. Use lowercase ASCII kebab-case matching `^[a-z0-9]+(?:-[a-z0-9]+)*$`; keep the full meaning in `TASK_NAME` and `TASK_SUMMARY`. |
| `TASK_SUMMARY` | Write one or two Korean sentences describing the work and expected outcome, using the clarification answer only when one was requested. |
| `START_DATE` | Generated by the script from Korean local time as `YYYY-MM-DD`. |
| `BASELINE_DATETIME` | Generated by the script from Korean local time as `YYYY-MM-DD HH:mm`, without an offset suffix. |
| `INITIAL_NEXT_ACTION` | Read reference instructions and entry documents when reference paths exist; otherwise define work units and completion criteria from the task scope. |
| `WORK_FOLDER` | Generated by the script: the repository-relative task folder for `sub`, or the whole repository for `global`. Never an absolute path. |

Normalize an empty or whitespace-only answer, `none`, or `없음` to `없음` for `START_NAME`, `REFERENCE_PATHS_OR_NONE`, and `ADDITIONAL_EDIT_SCOPE_OR_NONE`. Format supplied repository paths with backticks and separate multiple paths with commas. Preserve any short explanation that identifies a path's role.

## Plan the placement

Resolve `<skill-dir>` as the absolute directory containing this loaded `SKILL.md`, whether installed locally or globally. Resolve `<run-dir>` as the agent session's working directory (where the user opened the agent), even if a shell later changed directories. Check that Git, `uv`, and the bundled script and template are available; report anything missing before generating files. Then run, adding `--target` only in manual mode:

```text
uv run "<skill-dir>/scripts/create_task.py" --plan --run-dir "<run-dir>" --task-slug <TASK_SLUG> --target <PATH_AS_TYPED>
```

Pass the manual path exactly as the user typed it. The script strips surrounding quotes, accepts `\` and `/`, expands `~`, never expands environment variables, and resolves relative paths against `<run-dir>`. `--plan` changes nothing and prints UTF-8 JSON. If PowerShell shows non-ASCII text garbled, set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` and rerun.

| Mode | Condition | Destination | Template |
|---|---|---|---|
| auto | The run directory's repository root has `CLAUDE.md` or `AGENTS.md` | `<root>/docs/YYYY-MM-DD-<slug>/` | `sub` |
| auto | The root has neither file | `<root>/` | `global` |
| auto | The run directory is not in a Git repository | `<run-dir>` after `git init` | `global` |
| manual | The path is a repository root | the path | `global` |
| manual | The path is inside a repository (created if missing) | the path | `sub` |
| manual | The path is outside any repository (created if missing) | the path after `git init` | `global` |

The plan JSON contains `mode`, `destination`, `repo_root`, `template`, `work_folder`, `git_init`, `create_dirs`, `exclude_file`, `exclude_rules`, `nested_repositories`, `ignored_documents`, and `fingerprint`. If `--plan` fails (an existing file, a path below a file, a `.git` path, the home folder or a drive root as a project root, or a Git error), nothing changed: report the error and ask for another path.

## Final confirmation

Immediately before generation, run `--plan` again and show the user, in Korean:

- the absolute `destination` and the template (전역용 for `global`, 서브용 for `sub`)
- every side effect: `git_init`, each folder in `create_dirs`, and each line in `exclude_rules` with `exclude_file`
- warnings: `nested_repositories` (other Git repositories directly under the folder that will be initialized) and `ignored_documents` (committed documents Git would ignore; `.gitignore` is never changed)
- for `global`, when the request contained an additional edit scope, that it will not be applied

Do not change the filesystem before the user approves. If the user declines, change nothing and ask what to change. Reuse every answer already given, re-run `--plan` for the new location, and confirm again. When the new plan's `repo_root` differs from the previous plan, ask `REFERENCE_PATHS_OR_NONE` and `ADDITIONAL_EDIT_SCOPE_OR_NONE` again, because those paths are relative to a repository. When the new template is `sub` and question 4 was never asked, ask it; when it is `global`, drop the question 4 answer.

## Generate the task

After approval, run with the approved plan's `fingerprint`, passing each placeholder as one shell argument using quoting appropriate to the current shell:

```text
uv run "<skill-dir>/scripts/create_task.py" --run-dir "<run-dir>" --target <PATH_AS_TYPED> --task-name <TASK_NAME> --task-slug <TASK_SLUG> --task-summary <TASK_SUMMARY> --start-name <START_NAME> --reference-paths <REFERENCE_PATHS_OR_NONE> --additional-edit-scope <ADDITIONAL_EDIT_SCOPE_OR_NONE> --confirm <fingerprint>
```

Omit `--target` in auto mode. `uv` manages Python 3.11+ and the dependencies declared in the script, and the script resolves `assets/task-template` relative to its own installation. Before any side effect the script re-judges the placement and stops when it differs from the confirmed `fingerprint`, when any of the seven documents already exists, when a parent path or `evidence` is not a real directory, or when `global` receives an additional edit scope other than `없음`. It then creates folders, runs `git init`, appends escaped exact paths for the sub `AGENTS.md` and `CLAUDE.md` to the Git-resolved `info/exclude` of the repository that actually contains the folder (nested repositories, submodules, and linked worktrees included), and writes each document only if it does not exist. It never changes `.gitignore`.

- `placement changed since confirmation`: re-run `--plan` and confirm the new result.
- `documents already exist`: list the conflicting files from the error and ask how to proceed — move the existing files and rerun, or enter another path manually. Never overwrite and never silently choose another path, even in auto mode. A new path follows the re-entry rule above.
- Lines starting with `created:` after an error: generation failed after side effects began. Report every listed item verbatim. Nothing is rolled back; do not delete anything.

On success the script prints JSON with `status: created`. Report the destination, template, slug, `start_date`, `baseline_datetime`, and the side effects actually performed (`git_init`, `create_dirs`, `exclude_rules`). If the slug is rejected, generate a valid English slug and retry once.

`README.md` owns the shared overview, document map, team rules, and scope. `AGENTS.md` points to README; `CLAUDE.md` contains only `@AGENTS.md`. In the sub template both are local and uncommitted; in the global template both are official project instructions committed with the other five documents. `ROADMAP.md` is the briefing projection; `PROGRESS.md` is the detailed status source of truth. Keep the ROADMAP sequence table, adding a Mermaid `flowchart` with matching work IDs when branching, parallel execution, gates, or rollback paths make the flow complex. Do not add optional-module questions or generation branches.

## Growth after initialization

The generated README defines how later work-content and subtrack additions are incorporated: classify existing-work refinement versus an independent track, record confirmed scope changes and impacts in `decisions.md`, preserve existing IDs and completed history, then synchronize README scope, PROGRESS completion criteria/dependencies/next actions, and ROADMAP sequence. Create detailed documents only when needed and link them in the document map. An authorized content expansion does not expand editable paths. These are rules for working in the generated workspace, not a second generator mode or permission to modify the reference tasks.

## Example

`로그 레벨 조정` becomes `log-level`; `문서 구조 정리` becomes `documentation`; `사용자 인증 토큰 갱신 기능 개선` becomes `token-refresh`. References such as `docs/` and `src/` become `` `docs/`, `src/` ``. In a repository whose root has `AGENTS.md`, auto mode on 2026-10-26 places `log-level` in `docs/2026-10-26-log-level/`. If the destination already has documents, follow the conflict rule above; do not append arbitrary words, dates, or numbers automatically.

## Common mistakes

- Do not repeat answered questions or batch the remaining questions into one message.
- Do not skip the path mode question or the final confirmation.
- Do not ask question 4 for the global template.
- Do not generate without `--confirm` set to the fingerprint of the plan the user approved.
- Do not resolve the generator path relative to the target project; use the loaded skill's directory.
- Do not use Korean, romanized Korean, underscores, or spaces in `TASK_SLUG`.
- Do not turn the full task title into a long slug or shorten it with cryptic abbreviations or character truncation. Select the core topic words.
- During task creation, copy the asset template; do not customize the source assets for that task.
- Do not pre-generate optional modules; later work may add documents under the README growth rules.
- Do not include a UTC offset in the generated baseline time.
