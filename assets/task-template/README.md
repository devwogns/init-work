- 범위·정책·계약: 명시적으로 앞 결정을 개정한 확정 결정 → 승인된 명세·계약 → 실행 계획 → 안내·실행지시 순으로 따른다. 단순히 작성일이 최근이라는 이유로 승인판을 대체하지 않는다.

| 저장소 | 브랜치·정본 경로 | 역할·관련 작업 ID | 기준 커밋·확인일 | 정본·작업·보관 구분 |

- 문서 쓰기 정본과 코드 작업 브랜치를 구분하고, 외부 의존 브랜치는 소유 트랙을 표시한다.

- 브랜치 이름·과거 기록만으로 병합·배포 완료를 판정하지 않는다. 현재 진행 상태와 근거는 `PROGRESS.md`로 연결한다.

### 상태 갱신 규칙

- 조사·검증 결과는 `evidence/`에 먼저 남기고 확인 가능한 증거로 `PROGRESS.md`의 상태를 갱신한다.
- 구현·병합·배포·최종 완료를 구분한다. 구현 완료는 변경과 검증 결과, 배포 완료는 대상 환경·버전·반영 시각·검증·원복 가능 여부를 근거로 판정한다. 배포가 없는 작업에는 배포 조건을 적용하지 않는다.
- 최종 완료는 해당 작업의 완료 기준 충족으로 판정한다. 보류 시 사유와 재개 조건을 기록한다.
- `PROGRESS.md` 변경 시 기준 일시와 변경 이력을 함께 갱신한다. 단계·순서·게이트·현재 행동이 바뀌면 `ROADMAP.md`와 PROGRESS 기준일도 맞춘다.
- README의 지도·계약·규칙 변경 시 머리 문서 기준일을 갱신한다. 상세 진행 이력은 `PROGRESS.md`에 둔다.
- ROADMAP의 순서 표는 유지한다. 분기·병렬·게이트·원복 경로가 생기면 같은 작업 ID의 Mermaid `flowchart`를 추가한다.

### 역할

- 사용자·업무 담당자: 범위·정책의 미확정 판단과 작업별 승인 사항을 결정한다. 이미 확정된 요청을 반복 승인 대상으로 만들지 않는다.
- 에이전트: 허용 범위의 조사·구현·검증·문서 갱신을 수행하고, 정본에 없는 판단을 발견하면 결정 사항으로 제시한다.
- 별도 담당자·소유 트랙이 생기면 책임 범위와 인계 조건을 이 절에 기록한다.
- 팀 규칙은 이 README에 둔다. 에이전트 도구 운용 지침은 로컬 전용 `AGENTS.md`와 이를 참조하는 `CLAUDE.md`에 두며 두 파일은 커밋하지 않는다. 공통 산출물은 Git으로 추적한다.

### 작업 내용·하위 트랙 확장

1. 목적·결과·완료 기준이 기존 작업과 같으면 해당 범위를 보완한다. 독립 결과나 별도 완료 기준·의존성이 있으면 새 트랙으로 등록한다.
2. 확정된 확장은 `decisions.md`에 사유·추가·제외 범위·관련 작업 ID·기존 완료 기준과 일정·의존성에 미치는 영향을 기록한다. 미확정 선택은 열린 결정으로 구분한다.
3. 기존 ID는 변경·재사용하지 않는다. 새 트랙에는 사용된 최대 W 번호 다음 ID를, 기존 트랙 분할에는 상위 ID를 유지하는 미사용 하위 ID를 부여한다. 상위 작업에는 하위 ID와 완료 기준의 대응을 남기고 분할 자체를 완료로 판정하지 않는다.
4. README §1·문서 지도·식별자·결정 인덱스를 맞추고, PROGRESS에 완료 기준·의존성·다음 행동을 등록하며, ROADMAP의 순서·게이트를 갱신한다.
5. 기존 완료 이력과 증거는 보존한다. 추가 요구로 재검증이 필요하면 영향받는 부분과 이유를 새 작업으로 연결한다.

작업 내용의 확대는 편집 허용 경로의 확대가 아니다. 참조 경로나 편집 권한을 자동 변경하지 않는다.
